# Dongchedi: Technology Capability and Architecture Analysis

> Analysis date: May 2026
> Dimensions analyzed: technology architecture, AI capability, data systems, technical barriers, relationship with the ByteDance ecosystem
> Core question: How much of Dongchedi's technology is actually its own? How deep is its technical moat?

---

## I. Core Technology Stack and Architecture

### 1.1 Overview of the overall technology architecture

Dongchedi's technology system grew out of ByteDance, with **Golang** as the primary backend language (consistent with ByteDance's overall technology stack) and middleware built mainly on ByteDance's in-house systems. After spinning off, the company did not rebuild from scratch — instead it built deep vertical-domain customization on top of ByteDance's technology middle platform.

Based on publicly available technical talks and interview information, Dongchedi's technology architecture can be broken into the following layers:

| Layer | Core components | Source |
|------|---------|------|
| **Infrastructure layer** | Volcano Engine cloud services, containerized deployment | Provided by ByteDance/Volcano Engine |
| **Data layer** | A data warehouse at the hundred-petabyte scale, the DataLeap data platform, Flink real-time computing | ByteDance middle platform + in-house extensions |
| **Algorithm layer** | Recommendation algorithms, an automotive-domain LLM, an automotive multimodal VLM | ByteDance's recommendation engine + in-house vertical models |
| **Application layer** | AI car selection, AI online sales, 3D car viewing, VR test drives, content distribution | Primarily in-house |

### 1.2 What did it inherit from ByteDance?

**Inventory of inherited core assets:**

1. **The recommendation algorithm engine** — ByteDance's single most important technology asset. Dongchedi's "content finds the user" distribution logic directly reuses ByteDance's personalized recommendation algorithm framework, with feature engineering and model tuning applied specifically to the automotive vertical.

2. **Golang microservice architecture** — ByteDance's backend stack is built primarily on Go, and Dongchedi has carried this choice forward. Interviews explicitly require candidates to be proficient in Go, and new hires use in-house middleware.

3. **The DataLeap data engineering and governance platform** — ByteDance's one-stop data engineering platform. Dongchedi deeply integrates DataLeap's metrics-system capabilities and has built its own "Metrics Constellation Platform" business BI product on top of it.

4. **Flink real-time computing capability** — used for near-real-time and fully real-time data processing scenarios. ByteDance already has mature Flink capability in-house, and Dongchedi uses it directly.

5. **Volcano Engine cloud services** — all compute, storage, and networking infrastructure runs on Volcano Engine, including cloud compute and the Volcano Ark large-model development platform.

6. **Cross-platform user data** — automotive-interest user-profile data is shared across Douyin, Toutiao, and Xigua Video, forming a two-dimensional "interest–intent" model.

### 1.3 What was built in-house?

**The in-house work is concentrated mainly in the vertical application layer and the domain-model layer:**

1. **An automotive-domain LLM** — a vertical large language model trained on automotive-specific data on top of a general-purpose base model, which passed algorithm registration in December 2024.

2. **An automotive multimodal VLM** — a vision-language model that processes multimodal data such as vehicle photos and video.

3. **The "Dongchedi Smart Engine"** — comprising three components: an automotive knowledge-extraction graph, an automotive reinforcement-training engine, and an expert-tuning platform.

4. **3D/VR car-viewing technology** — 3D modeling, WebGL rendering, AR on-site viewing, etc., developed independently by an internal 3D team.

5. **The vehicle-testing system** — a self-built standardized testing process and data-collection/analysis system covering AEB, winter testing, range testing, and other dimensions.

6. **The Metrics Constellation Platform** — an in-house business BI system built on DataLeap, serving internal operational decision-making.

**Key judgment: Dongchedi's technology capability structure is roughly "70% inherited, 30% in-house."** The underlying infrastructure and core algorithm frameworks depend almost entirely on ByteDance/Volcano Engine, while the in-house component is concentrated in model training and application development for the automotive vertical. This is both an advantage (standing on a giant's shoulders) and a risk (limited independence).

## II. AI Recommendation Algorithm: Its Relationship to Douyin's Recommendation Engine

### 2.1 The core logic of the recommendation system

Dongchedi's recommendation system inherits ByteDance's core recommendation framework but applies deep customization for the automotive vertical.

**Relationship to Douyin's recommendation algorithm:**

| Dimension | Douyin recommendation | Dongchedi recommendation | Degree of sharing |
|------|---------|-----------|---------|
| Base framework | Collaborative filtering + deep learning | Same-origin framework | Highly shared |
| User profile | Interest tags, behavior sequences | Car preferences + purchase intent | Data interconnected |
| Content understanding | Video/image-text multimodal | Vehicle spec parameters + content | Partially shared |
| Distribution objective | User time-on-app, engagement rate | Lead conversion rate, decision efficiency | Independently optimized |
| Feature engineering | General-interest features | Vehicle preference, budget, region, purchase stage | Independently developed |

### 2.2 Cross-platform user-profile collaboration

Dongchedi and Douyin have deeply interconnected their user profiles:

- **On Douyin**: analyzes users' likes, comments, and shares on automotive content to gauge interest preferences
- **On Dongchedi**: analyzes search history, model-comparison frequency, and price-inquiry behavior to assess purchase-intent strength
- **Two-dimensional modeling**: forms a combined "interest–intent" profile

Actual performance data: after watching high-quality automotive content, users' propensity to search for cars is **1.4x** the platform average, and the conversion rate all the way through to a completed transaction is **2.7x** the platform average.

### 2.3 The unique value of the recommendation algorithm

Traditional automotive vertical media (Autohome, Yiche) operate on a "person finds content" model — users arrive with an explicit need and search for it. Dongchedi instead operates on "content finds the person" — reaching users proactively through the recommendation algorithm before they have formed an explicit purchase intent, intercepting them at the very top of the decision funnel.

**On the other hand**, the core engine behind this recommendation capability is not something Dongchedi built itself — it is a shared asset of ByteDance's technology middle platform. What Dongchedi has done is mostly vertical tuning on top of that foundation, not building from zero. What competitors cannot replicate is not the algorithm itself, but the scale of ByteDance ecosystem data behind the algorithm.

## III. Large-Model Applications: Deep Integration with Doubao/Volcano Engine

### 3.1 Large-model development timeline

| Time | Milestone |
|------|--------|
| 2023 | Began R&D on large-model applications |
| 2024 | Launched the AI Car Selection Assistant feature (beta) |
| December 2024 | The large-model algorithm passed domestic registration |
| July 2025 | Officially launched the AI Car Selection product and publicly unveiled the AI panorama |
| April 2026 | Debuted the "AI Xiaodong" smart assistant at the Beijing Auto Show, covering the five scenarios of selecting, buying, selling, using, and enjoying cars |

### 3.2 The AI panorama: a four-layer architecture

Dongchedi first publicly unveiled its AI panorama in July 2025; its architecture breaks into four layers:

**Data layer:**
- Dongchedi's proprietary database: over 50 million structured data records, with a vehicle-model library covering more than 76,000 models
- Professional public databases: industry-standard data sources
- User-authorized database: user behavior and preference data

**System layer:**
- Automotive knowledge-extraction graph — converts unstructured automotive knowledge into a structured knowledge graph
- Automotive reinforcement-training engine — reinforces the model for the vertical domain using techniques such as RLHF
- Expert-tuning platform — invites professional racing drivers, university scholars, and automotive editors to participate in data cleaning and annotation

**Model layer:**
- **The automotive-domain LLM** — fine-tuned for the automotive domain on top of the Doubao large model (formerly known as Yunque, developed in-house by ByteDance and released in May 2024)
- **The automotive multimodal VLM** — processes multimodal information such as vehicle images and video
- Already fully integrated with **Doubao 1.6**

**Application layer (AI agents):**
- **AI Search** — understands users' vague query intent and returns structured results
- **AI Car Selection** — recommends models based on user descriptions, with multimodal presentation
- **AI Online Sales** — helps dealers improve online customer acquisition and conversion
- **AI Xiaodong** (launched 2026) — covers the full lifecycle of selecting, buying, selling, using, and enjoying cars

### 3.3 How Doubao is specifically integrated

Dongchedi has fully integrated Volcano Engine's product suite:

- **The Volcano Ark large-model development platform** — for model training, fine-tuning, and deployment
- **Doubao large-model service** — provides base-level language understanding and generation capability
- **The large-model application firewall** — content safety and compliance filtering
- **Cloud compute** — GPU compute resources

Illustrative example: when a user enters "around 200,000 yuan, a good-looking EV for a woman," AI Car Selection extracts the key signals — "woman," "good-looking," "200,000-yuan budget," "EV" — analyzes the vague need and latent intent, recommends precise models, and presents them in multimodal form via images, text, and video.

### 3.4 An objective assessment of large-model capability

**Strengths:**
- Backed by the Doubao large-model ecosystem, giving access to first-tier base-model capability (Doubao 2.0 Pro is positioned against GPT 5.2 and Gemini 3 Pro)
- Deep accumulation of automotive-domain data (50 million+ structured records, 4,000+ vehicle models actually tested)
- Expert annotation improves the model's reliability in professional-use scenarios

**On the other hand:**
- The base large-model capability comes from Doubao rather than an in-house general-purpose large model. This means Dongchedi's AI capability ceiling is, to a significant degree, constrained by how fast Doubao itself evolves
- The automotive-domain LLM is, in essence, a vertical fine-tune on top of a general-purpose large model — a relatively low technical barrier. If Autohome or Yiche committed the resources, they could do similar vertical fine-tuning on other base models (e.g., Ernie, Tongyi)
- The large-model algorithm only passed registration in December 2024, and the formal product only launched in July 2025 — not the earliest in the industry

## IV. VR/AR Car-Viewing Technology

### 4.1 The 3D car-viewing technology stack

Dongchedi's 3D car-viewing feature was developed independently by an internal 3D team, staffed mainly by engineers born after 2000. The technical implementation spans several stages:

**Data capture:**
- Laser scanning: precisely captures vehicle geometry
- Photogrammetry: generates high-precision 3D models from multi-angle photographs
- Professional 3D scanning equipment + modeling software (Autodesk Maya, Blender, etc.)

**Rendering engine:**
- Built on **WebGL**, using rendering engines such as **Three.js** to deliver 3D display in the browser
- Supports 360-degree, no-blind-spot viewing of both interior and exterior
- LOD (Level of Detail) technology dynamically adjusts model detail level to optimize loading performance

**Core functionality:**
- Custom color switching
- Interior/exterior detail viewing
- Overlay of dimensional specs and pricing information
- AR on-site viewing: places the vehicle in a real-world scene via the phone's camera

### 4.2 VR car viewing and the PICO partnership

In March 2023, Dongchedi launched on ByteDance's **PICO** VR platform, becoming the first automotive-information app to reach the PICO app store:

- Covers more than **400 vehicle series** (including the Qin PLUS DM-i, Lavida, Li L7, Mercedes-Benz GLC, and other popular models)
- Supports experience modes including featured recommendations, custom viewing, and tailored search
- Fully replicates vehicles into virtual scenes, faithfully reproducing interior and exterior detail

### 4.3 3D simulated test drives

Dongchedi's 3D test-drive feature is fairly distinctive, supporting:
- **Free-drive mode** — users freely control the vehicle in a virtual scene
- **Performance test driving** — simulates acceleration, braking, and other performance experiences
- **Virtual driver-assist** — reproduces features such as adaptive cruise control, lane-departure warning, and lane-change assist

### 4.4 Technology-level assessment

**Strengths:**
- Among automotive-information platforms, the coverage and experience completeness of 3D/VR car viewing is best-in-class
- The collaboration with PICO VR is a synergy unique to the ByteDance ecosystem
- The team is young and iterates quickly

**On the other hand:**
- 3D car viewing is not a disruptive technology — WebGL plus Three.js is a mature, open-source stack, and competitors (e.g., Autohome) have equivalent development capability
- Actual usage of VR car viewing remains limited — PICO device market penetration itself is not high, so VR viewing functions more as a "showcase" feature than a core use case
- Producing and updating 3D models requires substantial manual effort; covering 400+ vehicle series is already no small feat, but relative to Dongchedi's total database of 76,000+ models, the coverage rate is still very low

## V. Vehicle Database and the Testing System

### 5.1 Database scale

| Metric | Data | Notes |
|------|------|------|
| Total structured data | 50 million+ | Includes model specs, pricing, configuration, etc. |
| Vehicle-model library coverage | 76,000+ models | Covers nearly every model sold on the market from 1999 to the present |
| Tested-vehicle database | 4,000+ models, 1 million+ data points | Collected through actual testing by an in-house team |
| Structured API fields | 20+ | Includes engine model, range, price band, 360-degree view, etc. |
| Update frequency | Real-time | Model specs, pricing, etc. are continuously synchronized |

### 5.2 The testing system

Dongchedi has built its own vehicle-testing team, recruiting testing engineers (with backgrounds such as vehicle engineering) responsible for:
- Dynamic performance testing of new and used vehicles
- Data collection and analysis
- Designing standardized testing procedures

**Testing coverage:** AEB emergency braking, winter range testing, acceleration/braking performance, driver-assist systems, and more.

### 5.3 Testing controversy and its implications

A winter-testing controversy in December 2023 exposed a real problem: **Dongchedi's testing standards lack industry-recognized authority.** Huawei, Great Wall, Geely, and other automakers questioned the consistency of its testing procedures (such as differences in vehicle-preparation steps, inconsistent air-conditioning temperature settings, and inconsistent standards for forcing engine intervention).

The China Association of Automobile Manufacturers subsequently called for new-energy-vehicle testing standards to be established — an implicit signal that, despite the sheer volume of Dongchedi's testing data, its professional rigor and authority remain contested.

**Data-source note**: the tested-vehicle database coverage figures come from Dongchedi's official disclosures at the July 2025 AI panorama launch.

## VI. The Metrics System and Data Warehouse Architecture

### 6.1 Data warehouse scale

Based on public sharing by Dongchedi's technical team (Zhihu/CSDN technical articles), the key metrics for its data warehouse are as follows:

| Metric | Scale |
|------|------|
| Data storage scale | Hundred-petabyte class |
| Daily routine production jobs | Tens of thousands |
| Compute-resource consumption | 100,000+ cores |
| Cumulative active metrics | 6,000+ |

### 6.2 Support for multiple latency scenarios

Dongchedi's data services cover three latency scenarios:

1. **Offline T+1 scenarios** — batch analysis updated the next day (e.g., daily/weekly report metrics)
2. **Near-real-time scenarios** — hourly/minute-level updates (e.g., real-time sales monitoring, popularity rankings)
3. **Fully real-time scenarios** — second-level responsiveness (e.g., real-time behavior-driven recommendations, AI conversation responses)

The implementation process differs across these three scenarios, but all are managed and mounted uniformly through the **DataLeap metrics platform**.

### 6.3 Building the metrics system

Building Dongchedi's metrics system spans three layers:
- **Foundational capability building** — metric metadata management standards (naming conventions, business definitions, tiering, catalog management, version management)
- **Metrics-service capability building** — using DataLeap to make metrics discoverable, queryable, and consumable
- **Application capability building** — in-house business BI products such as the "Metrics Constellation Platform," serving operations and decision-making

The underlying layer of this data system relies entirely on ByteDance/Volcano Engine's DataLeap platform, while the business-metric definitions and BI application development on top of it are Dongchedi's own accumulated work.

## VII. The Technology Team

### 7.1 Team size and distribution

Dongchedi has not disclosed exact headcount figures. Based on available information:

- **Overall company size**: revenue at the tens-of-billions-yuan scale, with operations spanning Beijing (headquarters), Hangzhou, and Chongqing; headcount is estimated at **2,000–4,000** (an estimate, not officially confirmed)
- **Technology/R&D share**: as a technology-driven platform, R&D headcount is estimated at 30–40% of the total, or roughly **600–1,500 people** (an estimate)
- **AI-related roles**: based on job postings, these include AI search engineers, conversational-assistant engineers, intelligent-pricing product managers, and NLP interns

### 7.2 Hiring profile

Based on official ByteDance/Dongchedi recruiting platform information:

| Role type | Skill requirements | Location |
|---------|---------|---------|
| AI search / conversational-assistant engineer | Bachelor's+, PyTorch/TensorFlow, LLM training/optimization experience | Beijing |
| Intelligent-pricing product manager | Bachelor's+, Python/SQL, understanding of the automotive industry | Beijing |

| Backend development engineer | Golang, Redis, databases, system design | Beijing/Hangzhou |

### 7.3 Technology-culture characteristics

- Dongchedi's hiring requirements call for candidates who "have a strong passion for the automotive industry"; its talent-management philosophy has been described as "loving cars is the number-one productive force"
- The technical interview process mirrors ByteDance's (multiple rounds, including algorithm questions, system design, and project experience), and the compensation structure also follows ByteDance's standard
- Uses Feishu People (Feishu HR) as its HR management system

### 7.4 Team assessment

**Strengths:**
- Inherits ByteDance's engineering culture (efficient, data-driven, fast-iterating)
- High hiring bar, able to attract top-tier engineering talent (leveraging the ByteDance brand)
- Competitive compensation (technical roles starting at 15k–25k yuan/month, senior engineers earning 400,000+ yuan/year)

**On the other hand:**
- After becoming independent, there is a risk that talent attractiveness declines — the "ByteDance" brand carries far more pull than "Dongchedi" alone
- Whether the core backbone of the technical team will stay with the spun-off Dongchedi remains uncertain
- The automotive vertical may be less attractive to top AI talent than ByteDance's core businesses (Douyin, TikTok, Doubao)

## VIII. Patents and Technical-Barrier Analysis

### 8.1 Patent status

**Frankly, public information on Dongchedi's patents is very limited.** Searches of the China National Intellectual Property Administration and third-party platforms turned up no detailed disclosure of Dongchedi's patent filing counts or categories.

Possible reasons:
1. Many of Dongchedi's core technologies (recommendation algorithms, large models, etc.) may be patented under ByteDance's name
2. As an application-layer company, Dongchedi's technical innovation is expressed more in product design and data accumulation than in underlying algorithmic innovation
3. Independence is recent (spun off at the end of 2023), so the number of patents filed under its own name may still be limited

### 8.2 Technical-barrier analysis

**Areas with relatively high barriers:**

| Barrier type | Strength | Notes |
|---------|------|------|
| Data accumulation | ★★★★ | A 76,000-model library, 4,000+ tested models, 50 million+ structured data records, a hundred-petabyte-class data warehouse — collecting and governing this data requires years of accumulation |
| ByteDance ecosystem synergy | ★★★★ | User-profile interconnection with Douyin's 310 million automotive-interest users, plus Volcano Engine infrastructure — competitors cannot replicate this |
| Recommendation-algorithm tuning | ★★★ | Vertical tuning experience built on ByteDance's recommendation framework, though the framework itself is not proprietary |
| Knowledge graph | ★★★ | Building the automotive knowledge graph requires professional manual annotation, which sets a certain bar |
| 3D/VR assets | ★★ | 400+ vehicle-series 3D models are an accumulated asset, but the technology stack itself has a low barrier |

**Areas with relatively low barriers:**

| Area | Notes |
|------|------|
| Base large-model capability | Dependent on Doubao, not proprietary. Competitors can adopt alternatives such as Ernie or Tongyi |
| WebGL 3D car viewing | An open-source technology stack; competitors such as Autohome already have similar features |
| Data-warehouse architecture | Built on DataLeap/Flink, an industry-standard approach |
| Vehicle testing | Testing standards lack industry consensus, and authority is contested |

### 8.3 The real depth of the technical moat

**Core judgment: Dongchedi's technical barrier is, at its core, not a "technology" barrier but an "ecosystem" barrier.**

Looked at individually, none of these technologies — the recommendation algorithm, the large model, 3D car viewing, the data warehouse — is something competitors fundamentally cannot catch up on. What is genuinely hard to replicate is the combined effect of these technologies within the ByteDance ecosystem:

- The user-reach power that comes from Douyin's 700 million daily active users
- The data flywheel from cross-platform user profiling
- The low-cost compute and tooling provided by Volcano Engine
- Training data continuously produced by 7.5 million content creators

This ecosystem barrier is both Dongchedi's greatest advantage and its greatest risk — because the barrier does not fully belong to Dongchedi itself; it belongs to ByteDance.

## IX. Relationship with ByteDance's Technology Middle Platform

### 9.1 Spin-off timeline

| Time | Event |
|------|------|
| August 2017 | Dongchedi launched as an internal ByteDance business |
| 2023 | Dongchedi's automotive content and commercialization fully merged with Douyin, Toutiao, and Xigua, with Dongchedi acting as the overall operator |
| December 2023 | Dongchedi became an independently operated entity, incorporated as its own legal company (a change in the controlling shareholder of Beijing Dongchedi Technology Co., Ltd.) |
| June 2024 | Completed roughly $600 million in financing (Sequoia China, KKR, General Atlantic, and others), at a valuation of roughly $3 billion |
| February 2026 | Reports emerged of plans for a Hong Kong IPO, seeking to raise $1.0–1.5 billion |

### 9.2 The boundary between shared and independent systems

**Heavily shared components:**

1. **Infrastructure** — everything runs on Volcano Engine cloud, with core business fully migrated to the cloud
2. **The recommendation-algorithm framework** — the underlying recommendation engine is shared with ByteDance's other products
3. **The data platform** — DataLeap, Flink, and other data tools are reused directly
4. **The large-model base** — the Doubao large model + the Volcano Ark development platform
5. **User data** — automotive-interest user data is shared across Douyin, Toutiao, and Xigua
6. **HR/collaboration tools** — uses Feishu and Feishu People for management

**Relatively independent components:**

1. **Vertical-domain models** — the automotive-domain LLM and automotive VLM are proprietary fine-tunes on top of general-purpose models
2. **Business applications** — product-level development such as AI Car Selection, AI Online Sales, and 3D car viewing
3. **The testing system** — its own in-house testing team and standardized processes
4. **Business BI** — in-house analytics tools such as the Metrics Constellation Platform
5. **The automotive knowledge graph** — cleaning, annotating, and structuring specialized data

### 9.3 Technical challenges after independence

**Short term**: after the spin-off, Dongchedi's relationship with ByteDance's technology middle platform has not, in substance, been severed. ByteDance retains control through its equity structure, technical infrastructure continues to run on Volcano Engine, and data continues to flow between the two. This means technical capability is unlikely to be negatively affected in the near term.

**Medium- and long-term risks:**
- If ByteDance's ownership stake declines after a successful IPO, the priority given to technical resources may be reassessed
- Volcano Engine's services would shift from "internal group calls" to "commercial customer procurement," potentially changing the cost structure
- Can Dongchedi independently take over the upgrade and maintenance of the recommendation-algorithm framework?
- The pace of Doubao's iteration is controlled by ByteDance, and Dongchedi can only accept it passively

**Reference comparison**: after Meituan became independent of the Tencent ecosystem, it gradually built its own technical infrastructure — but Meituan had a revenue base large enough to support that in-house investment. Whether Dongchedi's $3 billion valuation and tens-of-billions-yuan revenue scale are sufficient to support building an independent technology middle platform is a question worth continuing to watch.

## X. Summary: The Technology Capability Matrix

| Dimension | Rating | Core judgment |
|------|------|---------|
| Recommendation algorithm | ★★★★ | Inherits a core ByteDance asset; vertical tuning for automotive is mature, but the framework is not proprietary |
| Large-model applications | ★★★ | Fully integrated with the Doubao ecosystem, with deep vertical fine-tuning, but base-model capability is constrained by an outside party |
| Data system | ★★★★ | A hundred-petabyte-class warehouse, 6,000+ metrics, multi-latency scenario support — a mature architecture |
| 3D/VR technology | ★★★ | Full-featured, best-in-class experience, but a limited technical barrier |
| Testing capability | ★★★ | Broad coverage, large data volume, but authority of the standards is contested |
| Technical independence | ★★ | Deeply dependent on ByteDance/Volcano Engine; independent self-sufficiency remains to be proven post-spin-off |
| Technical moat | ★★★ | Data accumulation forms a real barrier; the technology itself has a limited barrier — the ecosystem barrier is the real core |

**One-sentence summary: Dongchedi's technology capability is, in essence, a projection of ByteDance's technology middle platform onto the automotive vertical.** Its strength lies not in underlying technological innovation, but in combining ByteDance's mature technology assets (recommendation, data, large models, cloud) with automotive-industry know-how. This "application-layer innovation plus platform-layer leverage" model is extremely efficient, but it also means technical independence is limited. Whether Dongchedi can gradually build its own independent technical capability after the IPO is one of the key variables in judging its long-term value.
